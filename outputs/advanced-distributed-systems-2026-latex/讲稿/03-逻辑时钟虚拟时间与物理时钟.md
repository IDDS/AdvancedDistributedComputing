# 第 3 讲：逻辑时钟、虚拟时间与物理时钟

## 一、本讲定位

本讲要让学生理解：分布式系统并不缺少“钟”，而是缺少一个所有进程都能可靠读取的全局时间。逻辑时钟编码因果，向量时钟保留并发，矩阵时钟表达知识的知识；Virtual Time/Time Warp 用虚拟时间组织仿真；NTP/PTP 则估计现实世界的物理时间偏差。

开场可问：**如果两个事件的物理时间戳分别是 10:00:00.100 和 10:00:00.090，能否断定后者是前者的原因？**不能。物理时钟可能偏移，网络延迟也可能造成观测顺序与因果顺序不一致。

## 二、统一框架：时间戳到底要保证什么

### 1. 三种要求

把时间系统的能力分成三档：

- **一致性**：若 e 发生在 f 之前，则 T(e) < T(f)；
- **强一致性**：T(e) < T(f) 当且仅当 e 因果先于 f；
- **并发识别**：如果两个向量不可比较，可以判断它们并发。

先提醒学生：标量时间可以保证第一条，但不能保证第二条；向量时间可以表达因果偏序，但成本随进程数增长。

### 2. 通用更新协议

用 R1/R2 组织所有逻辑时钟：

- R1：进程执行一个本地事件前，更新自己的时钟；
- R2：接收消息时，先合并消息携带的时间，再更新本地事件。

强调接收事件的顺序：**合并，再递增**，不能把“收到消息”简单当作普通本地事件。

## 三、Lamport 标量时钟

### 1. 算法

对每个进程维护一个整数 C：

- internal/send 前：C ← C + 1；
- receive(m) 时：C ← max(C, timestamp(m)) + 1。

讲授时不要马上进入复杂例子，先让学生说出为什么接收必须取最大值：接收者必须承认发送者已经知道的因果进度。

### 2. 完整例子

设三进程 P1、P2、P3：

1. P1 本地事件得到 1；
2. P1 发送 m，时间为 2；
3. P2 本地事件为 1；
4. P2 收到 m，更新为 max(1,2)+1=3；
5. P2 再发送 n，时间为 4；
6. P3 收到 n，若当前为 0，则更新为 5。

要求学生沿每条进程线和消息箭头检查：消息发送时间总小于接收时间。

### 3. 全序扩展与局限

仅比较整数时会有平局。使用二元组（时间戳，进程 ID）即可构造确定全序。

但一定要强调：

> 全序是确定性选择，不等于真实因果顺序。

如果两个事件并发，进程 ID 规则仍会强行决定一个先后。它适合排队、日志和确定性回放，不适合识别并发冲突。

反例：P1 的事件时间戳是 10，P2 的事件时间戳是 20，但 P2 与 P1 并无因果关系；不能说 P1 导致 P2。

## 四、向量时钟

### 1. 知识语义

对于 n 个进程，进程 Pi 保存向量 VT_i。分量 VT_i[j]=x 表示：Pi 已经知道进程 Pj 至少执行到第 x 个事件。

这句话比“第 j 个分量记录 Pj 的时间”更准确，因为它强调知识来源。

### 2. 更新规则

- 本地事件：只增加自己的分量；
- 发送：把向量附在消息上；
- 接收：逐分量取最大值，再增加接收者自己的分量。

例子：P1 的向量是 [2,0,0]，P2 当前是 [0,3,0]；P2 收到 P1 的消息后先取 max 得 [2,3,0]，然后接收事件使自身分量变为 [2,4,0]。

### 3. 向量比较

定义 V ≤ W：每个分量 V[j]≤W[j]；V < W：V≤W 且至少一个分量严格小。

- V < W：事件可能因果先于另一个事件；
- V 与 W 互不可比：两事件并发。

要特别说明“可能”的语义依赖于时间戳是否来自同一个正确的向量时钟算法。向量时钟提供的是因果偏序的精确编码。

### 4. 成本

每条消息通常携带 O(n) 个分量，每个进程保存 O(n) 状态。进程数很大时，系统需要稀疏向量、版本向量、区间编码或因果上下文压缩。

## 五、差分向量与矩阵时间

### 1. Singhal–Kshemkalyani 差分思想

向量变化通常是稀疏的。进程不需要每次发送完整向量，只发送自上次给该接收者发送后发生变化的分量。

讲授时用一个简单例子：

- 上次发送 [2,3,1]；
- 本次本地只改变第 1、3 分量；
- 消息只携带（1,3）对应的新值。

但必须说明 FIFO 要求：接收者必须按发送顺序应用差分，否则后来的稀疏更新可能在旧更新之前到达，无法恢复完整向量。

### 2. 矩阵时间

向量时钟回答“我知道每个进程到哪里”；矩阵时钟进一步记录“我知道其他进程认为别人到哪里”。

矩阵第 i 行可以看作 Pi 对全体进程知识的估计；矩阵的更高阶语义可用于稳定性判断、垃圾回收、消息因果和已知安全边界。

讲授时不要把矩阵当成纯粹更大的数组，要强调它表达的是知识层次提升，而不是简单精度提升。

## 六、Virtual Time 与 Time Warp

### 1. 为什么仿真需要虚拟时间

分布式仿真中，物理到达顺序可能与事件逻辑时间不一致。若严格等待所有可能的早期事件，仿真会很慢；乐观同步则允许进程先处理“看起来安全”的事件，迟到消息到达时再回滚。

### 2. Time Warp 的核心部件

一个进程需要保存：

- 当前虚拟时间；
- 输入队列，按虚拟时间排序；
- 已处理事件的状态历史；
- 已发送消息及其反消息信息；
- 输出队列和可撤销的副作用。

如果迟到消息的虚拟时间小于当前时间：

1. 找到最近的安全检查点；
2. 恢复状态；
3. 发送反消息撤销已经传播的输出；
4. 重新处理输入事件。

### 3. 完整五步例子

设 P1 在虚拟时间 20 处理事件，向 P3 发出影响；随后 P2 发送一个时间戳为 15 的迟到消息给 P1。

- Step 1：P1 先处理时间 20，看起来合法；
- Step 2：时间 15 的消息到达，揭示顺序冲突；
- Step 3：P1 回滚到 15 之前的检查点；
- Step 4：P1 发送反消息，P3 撤销由旧计算产生的状态；
- Step 5：P1 从 15 重新前进，得到新的时间线。

学生最容易误解的是“回滚只改本地状态”。必须强调：如果错误输出已经发送到别的进程，就必须用反消息或因果日志撤销外部影响。

### 4. Global Virtual Time

GVT 是所有进程当前虚拟时间和所有在途消息中最小值的安全下界。小于 GVT 的历史已经不可能被迟到消息影响，可以回收检查点和日志。

## 七、物理时钟与 NTP

### 1. 为什么还需要物理时间

逻辑时间适合因果和排序，但现实系统还需要：

- 证书有效期；
- 日志审计；
- SLA 和延迟测量；
- 跨区域故障时间线；
- 数据保留和合规。

### 2. offset、skew、drift

- offset：两个时钟读数之差；
- skew：某一时刻的频率/速率差异；
- drift：频率误差随时间累积造成的偏差。

用快钟、慢钟、理想钟图说明：即使初始同时，速率略有不同也会逐渐分离。

### 3. NTP 四时间戳

设客户端 A 发送请求时刻 T3，服务器 B 接收为 T1、发送回复为 T2，A 收到回复为 T4。

近似假设上行、下行延迟相等，则：

往返时延 delay = (T4−T3) − (T2−T1)

时钟偏移 offset = ((T1−T3) + (T2−T4)) / 2

推导时解释两项：

- T4−T3 是总往返时间；
- T2−T1 是服务器处理时间；
- 剩余部分是网络传播；
- 两个方向的时间差平均后估计偏移。

### 4. NTP 的边界

NTP 不能保证绝对精确；网络不对称、排队、服务器负载和攻击都会影响估计。需要高精度时可以使用 PTP，但更强精度通常意味着更严格的硬件、网络和部署条件。

在 AI 基础设施中，物理时间可用于 trace 对齐、GPU 训练阶段分析和跨节点故障审计；真正的因果判断仍应依赖逻辑时间或请求 ID。

## 八、课堂互动与收束

### 互动一：标量时间

给三进程执行图，让学生逐点计算 Lamport 时间，并指出哪些事件虽然时间戳可比较，却互不因果。

### 互动二：向量并发判断

给出 V1=[3,2,1]、V2=[3,1,2]，让学生判断。答案是互不可比，因此并发。

### 互动三：Time Warp 回滚

让学生预测迟到消息先影响本地状态，还是先影响已经收到旧输出的下游节点；要求指出反消息的传播路径。

### 收束句

> 逻辑时间回答“信息如何传播”，虚拟时间回答“仿真如何前进”，物理时间回答“现实世界何时发生”。三者不能互相替代，必须根据系统问题选择。

## 九、时间模型边界

向量时钟必须做完整的逐分量比较，单看某个分量不能证明因果。矩阵时钟的“知道别人知道什么”依赖具体更新规则，板书时要明确是合并完整矩阵还是只更新某一行。NTP 的 offset/delay 推导还隐含往返路径近似对称；墙上时间可被校时调整，持续时间和超时测量应使用单调时钟。最后强调：逻辑时间保留因果，不提供真实秒数；物理同步估计时间差，也不自动提供因果顺序。
