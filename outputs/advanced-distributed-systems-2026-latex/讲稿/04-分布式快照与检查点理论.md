# 第 4 讲：分布式快照与检查点理论

## 一、本讲定位

本讲围绕一个问题展开：没有共享内存、没有全局时钟、消息延迟又不可预测时，如何记录一个可以用于调试、检测和恢复的全局状态？

课堂主线是：

1. 全局状态由进程状态和信道状态共同组成；
2. 一致切面必须是因果向下闭包；
3. FIFO 信道可用 Chandy–Lamport marker 划界；
4. Non-FIFO 信道需要颜色、向量时间或计数；
5. 更一般的检查点理论需要用 zigzag path、Z-cone 和 R-graph 描述可恢复性。

## 二、为什么需要快照

### 1. 银行转账例子

先画两个账户进程 P1、P2 和一条消息：

- P1 先扣款；
- 转账消息在途；
- P2 尚未加款。

如果只读节点状态，会看到总额减少；如果把在途消息也记录下来，总额才守恒。

强调：快照不是“同时拍照”，而是寻找一个与原执行因果一致的状态组合。

### 2. 快照的用途

- 终止检测：所有进程空闲且信道为空；
- 死锁检测：快照中的等待图是否有环；
- 一致性检查：复制状态是否违反不变量；
- 调试：定位故障发生前的全局状态；
- 检查点：为恢复选择可重放的恢复线。

## 三、一致全局状态与切面

### 1. 形式化条件

全局状态由局部状态与信道状态组成。若一个接收已经属于过去，那么对应发送也必须属于过去；否则会出现“先看到结果、后看到原因”。

板书：

receive(m) 属于过去 ⇒ send(m) 属于过去

如果发送在过去、接收在未来，那么消息应该出现在对应信道的状态中。

### 2. Cut 的图形解释

逐条进程线选择一个切点。讲图时让学生先找是否存在消息箭头从右侧穿向左侧：

- 有：cut 不一致；
- 无：cut 可能一致，还需检查每条消息的端点。

注意“没有箭头穿越”是图形判据，但算法证明要回到因果闭包。

## 四、Chandy–Lamport 算法

### 1. 算法直觉

Marker 不是普通数据消息，而是快照边界的控制标记。FIFO 保证 marker 不会被同一信道上更早发送的数据消息越过。

### 2. 发起规则

发起进程：

1. 记录本地状态；
2. 在所有出信道发送 marker；
3. 开始记录所有入信道上 marker 到达前收到的数据消息。

### 3. 接收规则

进程第一次收到 marker：

1. 记录本地状态；
2. 将该 marker 对应信道记为空；
3. 在其他出信道发送 marker；
4. 开始记录其他入信道中的数据消息。

之后从某个信道再次收到 marker：

- 停止记录该信道；
- 此前记录的数据就是该信道状态。

### 4. 完整例子

设置 P1、P2、P3：

- P1 发起并记录状态；
- P1 给 P2、P3 发 marker；
- P2 在收到 P1 marker 前收到一条普通消息，必须记录为 P1→P2 信道状态；
- P2 收到 marker 后记录本地状态，并向 P3 继续传播；
- 所有进程收到来自每条入信道的 marker 后，快照完成。

课堂推演时不要直接给答案，问学生每收到一个 marker 时：

1. 本地状态是否已经记录？
2. 哪条信道开始/停止记录？
3. 哪些普通消息属于快照中的信道状态？

### 5. 正确性

安全性：不会把接收记录在快照中却遗漏发送；不会把 marker 之后的数据误记为快照信道状态。  
活性：在可靠 FIFO 信道和未永久崩溃的进程条件下，marker 最终传播完。

复杂度：控制消息通常为 O(|E|)，每个进程记录一次本地状态，每条信道记录边界消息。

## 五、并发发起与区域快照

多个进程同时发起时，可能有多组 marker 同时传播。讲解重点不是记住某个算法名，而是理解：

- 记录阶段可以并行；
- 不同发起者的快照需要区分；
- 区域或隐式生成树可以减少重复广播；
- 跨区域信道必须明确谁负责记录和合并。

## 六、Non-FIFO 信道

### 1. Marker 为什么失效

如果普通消息可以越过 marker 到达，接收者无法判断这个普通消息是在快照边界之前还是之后发送的。此时 marker 不再天然代表边界。

### 2. Lai–Yang 颜色法

给进程和消息染色：

- 初始为白；
- 进程记录快照后变红；
- 红进程发送的消息为红；
- 白进程收到红消息时必须先记录本地状态；
- 白消息仍可能属于旧历史，需要根据发送者颜色和接收时机判断。

重点是：边界语义嵌入应用消息，而不是依赖信道顺序。

### 3. Mattern 方法

用向量时间或消息计数选择边界，并通过计数守恒判断哪些消息仍在途。这里可与第 3 讲的向量时钟连接：时间戳帮助描述“快照边界已经覆盖哪些因果前驱”。

## 七、因果交付下的快照

因果有序信道本身提供了额外同步。若一个接收事件已经交付，而其因果前驱的消息还未出现，就违反因果交付；因此某些信道状态可以通过发送/接收计数直接推断，减少显式控制消息。

讲 Acharya–Badrinath 和 Alagar–Venkatesan 时，重点比较：

- 需要携带多少计数；
- 是否依赖 FIFO/因果顺序；
- 能否检测到所有未完成消息；
- 控制开销和实现复杂度。

## 八、Zigzag path 与一致检查点

### 1. 为什么没有因果路径仍可能不一致

检查点可以沿进程线前后移动，但消息路径可能交替穿越不同进程线，形成 zigzag path。它比普通 happened-before 更适合描述“两个检查点是否能共同出现在某个一致全局状态”。

### 2. Zigzag cycle

若检查点集合 S 周围存在 zigzag cycle，说明沿着一系列局部检查点和消息关系无法同时选择一个一致恢复线。某个检查点即使没有普通因果前驱，也可能不能加入。

### 3. Z-cone 与 C-cone

- C-cone：按普通因果路径定义的候选区域；
- Z-cone：按 zigzag path 定义的更严格候选区域；
- 因果路径是 zigzag path 的特例，因此 Z-cone 通常更小。

用中文重绘的 Z-cone 图讲三个区域：

1. 能通过 Z-path 到达 S；
2. 与 S Z-无序，是候选区；
3. S 能通过 Z-path 到达。

## 九、R-graph 与检查点枚举

把局部检查点区间和消息依赖抽象成 R-graph：

- 顶点是检查点；
- 边表示连续检查点、消息或 volatile checkpoint 依赖；
- 环表示不可能同时选择的恢复组合。

枚举算法的讲法：

1. 从每个进程选择一个候选检查点；
2. 检查是否形成 Z-cycle 或 R-graph 环；
3. 若冲突，回溯到某个进程选择下一个检查点；
4. 找到无环组合后得到一致快照。

要明确这类算法可能是指数复杂度；理论上可行不等于工程上适合频繁运行。

## 十、课堂互动与收束

### 互动一：追踪 marker

给三进程 FIFO 图，要求学生标出每个进程的本地记录时刻和每条信道最终记录的消息。

### 互动二：Non-FIFO 反例

让学生设计一个普通消息越过 marker 的序列，并说明为什么接收端无法仅靠 marker 判断边界。

### 互动三：恢复线

给 P1、P2、P3 各三个检查点，加入一条跨进程消息，让学生寻找一个不含 orphan message 的恢复组合。

### 收束句

> 快照把“全局状态”从一个不可能同时读取的对象，变成一个因果一致的组合。后面的终止检测、死锁检测、检查点恢复，都是在不同目标下重复使用这套思想。
