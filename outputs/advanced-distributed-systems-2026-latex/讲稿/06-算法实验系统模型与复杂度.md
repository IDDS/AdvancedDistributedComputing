# 第 6 讲：算法实验、系统模型与复杂度

## 一、本讲定位

本讲把“会读伪代码”推进到“会验证系统”。学生要理解：算法正确性和复杂度都依赖系统模型；实验不能只报一个 O()，还要说明消息数量、消息大小、并行度、恢复成本和测量方法。

## 二、先写清系统模型

### 1. 拓扑层次

区分：

- 物理拓扑：机器、交换机、链路；
- 逻辑拓扑：算法认为哪些节点相邻；
- 覆盖拓扑：应用层 overlay 的邻居关系。

AI 模型分发可能在物理上跨多个机架，在逻辑上却只连接每个节点的若干代表。复杂度必须说明是按物理边还是逻辑边计算。

### 2. 算法类别

讲集中式/分布式、对称/非对称、anonymous/uniform/adaptive、确定性/非确定性时，不要用术语替代理解。给学生一个算法并问：

- 节点是否知道自己的 ID？
- 是否知道网络规模 n？
- 是否有预先指定根？
- 是否允许随机数？
- 节点能否访问全局拓扑？

这些问题会直接改变可解性和复杂度。

### 3. 故障与信道

区分 crash、omission、timing、Byzantine，以及链路故障和认证能力。Wait-free 不是“没有等待消息”，而是某个进程即使其他进程停顿，也能在有限自身步骤内完成。

## 三、复杂度不要只写 O()

建议板书一张指标表：

| 指标 | 问题 |
|---|---|
| 消息数 | 发了多少控制和数据消息？ |
| 消息大小 | 每条是否携带 O(n) 元数据？ |
| 时间 | 同步轮数或关键路径长度？ |
| 局部工作 | 每个节点比较、排序、存储多少？ |
| 并发度 | 能否重叠通信和计算？ |
| 恢复成本 | 故障后要重做多少工作？ |

说明 O(m) 消息不一定优于 O(n log n) 的算法，因为前者可能每条消息携带完整拓扑，或关键路径更长。

## 四、同步生成树实验

### 1. 实验目标

在固定图上改变：

- 节点数 n；
- 边数 m；
- 直径 D；
- 根节点位置；
- 消息延迟。

测量生成树构造时间、消息数和树高。

### 2. 正确性检查

每次运行后检查：

1. 根没有 parent；
2. 每个非根节点恰有一个 parent；
3. parent-child 边存在于原图；
4. 从每个节点沿 parent 最终到达根；
5. 树边数为 n−1。

不要只看程序“结束了”，必须用不变量自动验证。

## 五、异步生成树实验

### 1. 为什么需要 REJECT

异步时多个邻居都可能先发探索消息。没有 REJECT，节点会同时认多个 parent，形成环或重复树枝。

### 2. 实验设计

控制一条消息延迟，观察：

- parent 是否变化；
- ACCEPT/REJECT 是否成对；
- root 是否收到所有子树完成报告；
- 是否出现“报告完成后又被激活”的竞态。

要求学生记录事件日志，而不是只记录最终树。

## 六、并发发起者实验

比较三种策略：

- 最高 ID 胜出；
- 多个树并行运行；
- 先合并 root，再进行一次广播。

指标包括消息数、收敛时间和抑制消息数。让学生看到：算法设计经常是在“更快收敛”和“更少控制消息”之间做选择。

## 七、AI 基础设施实验

### 实验一：拓扑对模型分发延迟的影响

比较链式、星型、树型和机架感知树：

- 同一权重大小；
- 同一总带宽；
- 随机注入链路延迟；
- 记录首个节点完成、全部节点完成、尾部节点完成。

讨论：总吞吐相同，为什么完成时间仍可能不同？

### 实验二：故障模型对 checkpoint 收集的影响

注入：

- 一个 worker crash；
- 一个 worker 慢 5 倍；
- 一条链路丢包；
- checkpoint 元数据延迟。

观察协调式和非协调式收集的恢复时间。

### 实验三：公平性与自适应复杂度

让不同任务争用 GPU 或网络。除了平均延迟，记录 P95/P99、最大等待时间和资源利用率。算法“吞吐高”不代表公平。

## 八、实验报告模板

要求学生按以下结构写：

1. 问题和系统模型；
2. 算法状态与消息；
3. 正确性不变量；
4. 实验变量、对照组和随机种子；
5. 结果图和误差解释；
6. 复杂度分析；
7. 故障/异常案例；
8. 局限和下一步。

## 九、课堂互动与收束

让学生对同一算法写两种复杂度：

- 理论最坏情况；
- 给定拓扑和 workload 下的实测情况。

收束句：

> 分布式算法的实验不是给理论“配一张性能图”，而是检查模型、实现和不变量是否真的对应。下一讲我们将讨论消息顺序：同一组消息以什么顺序被观察，会改变哪些算法可以实现。
