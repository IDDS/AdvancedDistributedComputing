# 第 1 讲：系统导论与 AI 基础设施

## 一、本讲定位

本讲不急于讲算法，而是帮助学生建立一个持续使用 17 周的观察框架：分布式系统由多个自治实体组成；它们通过通信协作；系统运行在不确定的时间、网络和故障条件下。学生最后应能把一个真实系统描述成“参与者—状态—消息—假设—性质”。

建议开场提问：**“如果把一台机器拆成十台，程序会自动变成分布式系统吗？”**答案不是简单的“会”。真正的变化来自独立故障、独立时钟、消息延迟、局部观测和跨节点协调。

## 二、开场与课程主线

### 1. 先告诉学生这门课解决什么问题

可以这样讲：

> 我们研究的不是某一个中间件 API，而是一类反复出现的困难：一个决定可能需要多个节点共同完成；每个节点只看到局部状态；消息可能迟到、重复、丢失或乱序；节点可能崩溃，甚至会出现恶意行为。我们要学习的是，在这些条件下如何仍然证明系统正确。

把全课压缩成四个问题写在板书上：

1. **时间**：谁先发生？如何判断因果？
2. **状态**：如何得到全局视图？如何保存和恢复？
3. **协调**：如何排序、选主、互斥、达成共识？
4. **故障与安全**：如何发现异常、隔离影响、恢复服务？

强调课件中反复出现的主线：

> 物理分布，逻辑集中；个体独立，整体协作。  
> 先写假设，再谈算法；先找不变量，再谈正确性。

### 2. 用 Lamport 的“不可见故障”建立直觉

不要把 Lamport 的话讲成名人名言，而要解释它的技术含义：一个进程并不知道另一个进程是否发生了故障，但它必须根据消息是否到达、是否超时、是否回复来决定下一步。**未知本身就是系统状态的一部分。**

举例：服务 A 调用服务 B。A 没有收到回复，至少有四种可能：

- B 没有收到请求；
- B 收到后正在处理；
- B 已经处理完，但回复在网络中延迟；
- B 已经处理，回复丢失，A 无法知道结果。

由此引出：重试是否安全取决于操作是否幂等；超时不是故障证明；“没有观察到成功”不等于“操作没有发生”。

## 三、分布式系统的定义与两个张力

### 1. 定义不要只背“多个独立计算机”

建议把定义拆成三个条件：

- **多个自治实体**：每个进程、节点、服务或设备有独立的控制流和局部状态；
- **通信协作**：实体通过消息、共享存储或网络接口影响彼此；
- **对外提供整体行为**：用户希望看到一个可用、可理解的系统，而不是一堆互不相干的机器。

在板书上画：

局部状态 P1 + 局部状态 P2 + 消息流 + 协调协议 = 系统行为

强调等号不是数学恒等式，而是设计责任：系统行为并不会自动出现，必须由协议和不变量保证。

### 2. 自主性与耦合性

“自主”意味着节点可以独立执行、失败和恢复；“耦合”意味着节点的行为又会相互影响。两者同时存在，才产生分布式系统的难题。

例子：微服务中的订单服务和库存服务。它们可以独立部署、独立扩容，但一次下单又要求订单状态和库存状态协调。若只强调自主性，会忽略一致性；若只强调耦合性，会把系统设计成一个不可扩展的中心服务。

### 3. 从单机视角切换到系统视角

在单机程序中，函数调用通常表现为“调用—返回”；在分布式系统中，远程调用还包含网络排队、序列化、远端进程调度、超时与重试，以及结果已经产生但没有返回的情况。

要求学生把一次 put(key,value) 拆成请求、路由、分片、主副本、日志、确认、回复等阶段。这里不需要立刻讲具体数据库实现，目的是让学生习惯问“这一步跨了哪些边界”。

## 四、真实系统案例：从局域网到大模型

### 1. 局域网案例

讲图时不要逐个读“文件服务器、邮件服务器”，要抓住三个观察：

1. 主机独立，服务共享；
2. 网络把局部资源组织成一个可访问空间；
3. 交换机、路由器和防火墙都是系统行为的一部分。

追问：如果交换机队列变长，用户看到的会是什么？答案可能是延迟升高、超时、重试、重复请求和级联拥塞。这样把网络性能连接到上层语义。

### 2. Tair、OceanBase、Elasticsearch

用同一个讲法比较三个系统：

- **路由**：请求如何找到正确的分片或协调节点？
- **状态**：谁保存元数据、主副本和成员信息？
- **复制**：副本之间如何同步？故障时谁接管？
- **观测**：用户如何知道请求慢在路由、存储还是副本同步？

强调“一个 key 的读写”背后可能经过配置服务、分片路由、主备复制和客户端重试。学生以后学一致性、故障检测、共识时，都会回到这条路径。

### 3. 边缘计算和大规模深度学习

边缘计算展示地理分布：云端有全局数据和大资源，边缘有低延迟和局部自治。大模型训练展示另一种分布：计算节点越多，通信和同步越成为主要路径。

可以用简单公式说明同步放大：

一步训练时间 ≈ max（各节点计算时间）+ 梯度通信时间

如果某个节点偶尔慢 200 ms，所有节点都必须等它，尾延迟就会成为整体吞吐的上限。这为后面的同步/异步模型、检查点、故障恢复和集合通信埋下伏笔。

### 4. Ray、Meta AI 与 Kubernetes 推理

讲 Ray 图时，建议按层次从上到下：

- AI 应用层：数据、训练、调参、服务和强化学习；
- Ray Core：Task、Actor、Object；
- 控制状态：任务表、对象表、事件日志；
- 计算和网络资源：CPU/GPU、对象存储和集群互联。

讲 Kubernetes 推理图时，把请求路径说完整：

客户端请求 → 推理网关 → 模型路由 → 感知负载/KV Cache 的调度器 → 推理副本

强调这里出现了四个分布式系统问题：

- 路由状态是否新鲜？
- KV Cache 属于哪个副本？
- 副本扩缩容如何不影响正在处理的请求？
- 一个副本“活着但不推进”时，谁来判断？

说明 PD 分离（Prefill/Decode 分离）时，不要只说“拆成两个服务”。应说明：预填充和解码的计算、显存、通信特征不同，拆分后需要共享前缀缓存、请求状态和调度信息；因此，性能优化同时增加了跨服务一致性和故障恢复问题。

## 五、并行系统与互联结构

### 1. UMA、NUMA 与消息传递

把三种组织方式放在一张表中讲：

| 组织 | 程序看到的抽象 | 主要代价 |
|---|---|---|
| UMA | 共享内存、近似统一访问 | 总线和内存争用 |
| NUMA | 共享地址空间、访问代价不均 | 远端访问和放置 |
| 消息传递 | 私有内存、显式发送接收 | 通信、序列化和协议 |

强调：共享内存不是“没有通信”，只是通信由缓存一致性和硬件协议隐式完成；消息传递不是“没有共享状态”，而是应用显式管理状态复制。

### 2. Omega、Butterfly、Mesh、Torus、Hypercube

这些拓扑不要求学生记住每一条连线，而要理解三个指标：

- 路径长度；
- 节点度；
- 是否存在瓶颈或对称性。

讲 Omega 网络时，可以给一个 3 位目的地址，说明每一级交换单元根据一位地址决定上/下端口；再问学生：如果多个流量集中到同一出口，会发生什么？答案是局部交换单元拥塞，即便总带宽看起来很大。

### 3. Send/Receive 原语

这一部分必须避免把同步/异步、阻塞/非阻塞混成一组二元选项。建议分别回答：

- **同步/异步**：发送完成是否依赖接收端参与？
- **阻塞/非阻塞**：调用者是否立即返回？

用四类 Send 做时间线时，先标出四个事件：调用、消息离开发送端、消息到达接收端、调用返回。然后说明：

- 同步阻塞：发送者等到握手或接收条件满足；
- 同步非阻塞：调用快速返回，但句柄必须等待完成；
- 异步阻塞：发送可以独立完成，但调用者仍等待本地完成条件；
- 异步非阻塞：调用立即返回，完成由回调、轮询或事件通知暴露。

这里的重点不是背四个名字，而是让学生知道：算法的正确性依赖“何时可以安全重用缓冲区”“何时消息一定可见”“进程是否可能被发送阻塞”。

## 六、系统挑战与设计目标

### 1. 透明性不是越多越好

透明性可以隐藏位置、迁移、复制、并发、故障、性能等差异。但完全透明会让用户失去做出正确决策所需的信息。

例子：对象存储把跨区域访问隐藏成一次普通读操作。接口透明了，但延迟、费用和一致性语义没有消失。如果系统完全不暴露这些特征，用户无法解释性能和成本。

### 2. 四个设计目标

建议用“资源访问、开放性、可扩展性、质量”四个词收束：

- 资源访问：让远程资源可发现、可共享、可控制；
- 开放性：接口、语法和语义允许不同实现互操作；
- 可扩展性：规模、地理范围和管理域变化时仍可工作；
- 质量：性能、可靠性、安全性和可维护性之间有明确取舍。

### 3. 算法挑战

给学生一张“挑战—后续章节”映射：

- 执行模型与动态图 → 第 2 讲；
- 时间与全局状态 → 第 3、4 讲；
- 协调、互斥、共识 → 第 7、10、14 讲；
- 复制和一致性 → 第 12、15 讲；
- 故障检测与恢复 → 第 9、11、12、13 讲；

## 七、课堂互动与收束

### 互动：假设审计

让学生任选一个熟悉系统（CDN、Kubernetes、数据库或推理服务），写出：

1. 三个系统假设；
2. 三个可能故障；
3. 三个可观测证据；
4. 一个不能完全隐藏的分布特征。

### 课末收束句

> 今天我们没有证明某个算法，但已经学会了如何提问。以后看到一个分布式协议，先不要问“它用了什么框架”，先问：参与者是谁？状态在哪里？消息如何到达？系统假设是什么？它承诺安全性、活性还是性能？

### 课后作业建议

- 将一次 Kubernetes 推理请求画成消息/状态图；
- 对比 UMA、NUMA、消息传递三种模型；
- 写一页“八个分布式系统谬误”在 AI 推理服务中的具体表现。

## 八、Send/Receive 分类的边界

本讲四种 Send 时间线采用“同步/异步 × 阻塞/非阻塞”的二维抽象。讲授时要主动提醒：MPI 的 standard、buffered、synchronous、ready 是另一组发送模式，仍可分别具有 blocking/nonblocking 变体。学生判断一个原语时，应先回答三个问题：发送方用户缓冲区何时可复用、接收方何时必须参与、调用何时把控制权交还给程序。不要把课件中的四条时间线直接当成 MPI 的完整语义。
