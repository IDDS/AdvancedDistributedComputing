# 第 17 讲：P2P、自稳定与系统综合

## 一、本讲定位

最后一讲把课程重新连接起来：P2P 没有固定中心和稳定成员；DHT 解决对象定位；Chord/CAN/Tapestry 展示不同覆盖几何；自稳定要求系统从任意状态恢复到合法状态；AI 基础设施则把对象、owner、副本、缓存和路由放在同一系统里。

## 二、P2P 与客户端—服务器

客户端—服务器依赖中心目录、固定服务和明确边界；P2P 强调节点对称、自组织和动态加入/离开。

Napster 是一个很好的过渡例子：中心目录负责索引，文件传输仍可端到端。由此说明 P2P 不是“完全没有中心”，而是把控制面和数据面分离。

## 三、覆盖网络与索引

### 1. 结构化与非结构化

- 结构化：对象 key 映射到确定 owner，查找可证明；
- 非结构化：随机邻居、flooding 或 random walk，适合复杂语义但难保证最坏路径。

### 2. 一致性哈希

节点和 key 映射到环上。加入/离开时只需迁移局部区间，减少全局重分布。

讲解时明确：一致性哈希减少迁移范围，但不自动解决热点、复制、故障和成员视图一致。

## 四、Chord

### 1. 环和 successor

key 顺时针找到第一个节点 successor。若只有 successor 指针，查找最坏 O(n)。

### 2. Finger table

每个节点保存距离为 1、2、4、8… 的指针。查找时选择不超过目标的最远 finger，把剩余距离指数缩小，平均/期望 O(log n)。

### 3. 完整例子

节点 N5 查找 key=70：

1. N5 查看 finger，选择不超过 70 的最远节点；
2. 跳到 N32；
3. 再跳到 N64；
4. successor 是 N80，因此 key=70 归 N80。

### 4. 加入与 churn

新节点加入后需要 successor/predecessor 修复、finger 修复和键迁移。churn 中加入、主动离开和失效并不相同，恢复协议必须分别处理。

## 五、CAN 与 Tapestry

CAN 把 key 放入 d 维 torus 空间，路由按坐标逐维靠近；Tapestry 按前缀逐位匹配。它们的“几何”不同，但共同目标是让局部路由逼近全局对象。

比较：

- 路由表大小；
- 跳数；
- 节点加入/离开维护；
- 对网络延迟和故障的敏感性。

## 六、搜索、复制与 churn

非结构化 flooding 简单但消息爆炸；random walk 节省消息但可能漏目标。搜索评价要同时看：

- 查找成功率；
- 平均/尾部跳数；
- 消息数；
- 热点负载；
- churn 下的稳定性。

对象热度常呈 Zipf 分布，因此热门模型、tokenizer 和 KV Cache 需要更多副本；复制增加可用性，却增加一致性和迁移成本。

## 七、自稳定

### 1. 定义

系统从任意初始状态出发：

- convergence：有限时间进入合法状态；
- closure：进入合法状态后保持合法。

这与“从干净启动开始正确”不同，适合网络丢状态、配置损坏或控制面重启后的恢复。

### 2. Dijkstra Token Ring

多个 token 可能存在。特殊节点通过改变颜色/值打破对称，令 token 沿环传播，最终只保留一个合法 token。

讲完整例子时给出任意状态，例如 [2,2,0,1]，让学生逐步执行规则，观察不合法状态如何收敛。

### 3. 自稳定 BFS

节点通过比较 root ID 和距离逐步选择 parent。即使初始 parent 指针错误，局部规则最终也会把系统拉回一棵以最小 root 为根的 BFS 树。

## 八、AI 基础设施映射

- 训练数据：内容寻址，key 是 hash，owner 是存储节点；
- 模型权重：热点复制和版本路由；
- KV Cache：动态、易失、热点对象；
- GPU 调度：overlay 上的资源 owner 和租约；
- Ray/KubeRay：控制面维护任务与对象，数据面执行；
- 自稳定配置：节点从错误参数恢复到可服务状态。

强调“自稳定”不能掩盖所有错误：如果外部副作用已经发生，仍需版本、幂等和审计。

## 九、综合演练

### 题目一：模型分发 overlay

要求设计：

- key 如何映射 owner；
- 模型如何复制；
- 节点加入/离开如何迁移；
- 如何检测旧副本；
- 如何在网络分区下停止错误发布。

### 题目二：故障时间线

给出 GPU 节点失效、leader 超时、checkpoint 在途、缓存版本不同的时间线，要求学生综合使用：

- 故障检测；
- fencing；
- 一致快照；
- 共识日志；
- 版本化缓存。

### 题目三：证明 closure

给一个自稳定规则，说明一旦所有节点满足 parent、distance 和 root 不变量，下一步执行不会破坏它。

## 十一、综合设计的边界检查

Chord 的 finger 过期时可以回退到 successor 链保证正确性，但 churn 期间的副本迁移、并发 join/leave 和故障恢复仍需要额外协议。Dijkstra 自稳定算法的经典结论依赖环拓扑和 $K\ge n$ 等条件，换成任意网络或多个 token 后必须重新分析 closure 与 convergence。CAN、Tapestry、Chord 的逻辑邻居也不一定是物理近邻；AI 数据和 KV Cache 系统还要同时考虑带宽、容量、拓扑和租户隔离。
